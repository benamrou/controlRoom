About the Critical Alert Watchdog {{ showHelp ? 'Hide' : 'Show' }}

This screen lets you protect critical alerts from silent failure. For every watch contract you create here, a background scanner checks ALERTLOG on a schedule. If the expected log row never arrives, the watchdog runs your recovery shell, writes the outcome to ALERTWATCHLOG, and pages an admin by SMS + email.

Quick start

  1. Click CREATE.
  2. General tab — pick the Alert (LALTID) and, optionally, a LALTPARAM LIKE pattern (e.g. %CNT0000000004_5%) to target one instance of a fan-out alert.
  3. Use Test pattern to confirm the pattern matches real rows from the last 24 h.
  4. Schedule tab — set the cron when the log entry is expected, plus the grace period.
  5. Recovery shell tab — edit the pre-filled curl template so it re-fires the missed alert (typically a call to /api/notification/).
  6. Save. The next scan will start enforcing the contract.

Key concepts

  • AWTPARAMLIKE — Oracle LIKE pattern matched against ALERTLOG.LALTPARAM. Empty = match by LALTID alone. Required for fan-out alerts that fire many rows per run.
  • Grace (sec) — how long after the expected fire time before declaring it missed. Default 120 s.
  • Max retries / scan — hard cap so a long-broken alert can't trigger a fire-storm. Default 3.
  • Catch up at startup — also evaluate this watch when the Node app restarts.
  • Active — pause/resume the contract without losing it.

Day-to-day

  • Last recovery column shows the most recent ALERTWATCHLOG status per watch (RECOVERED / FAILED / TIMED_OUT / never).
  • opens the recovery history for one watch.
  • RUN NOW in the top-right forces an immediate scan; useful right after creating a contract or to re-check after a system event.
  • A FAILED row is not auto-retried. To force a retry after fixing the root cause, delete the matching ALERTWATCHLOG row.

Architecture

  • ALERTWATCH — the contracts you define here.
  • ALERTWATCHLOG — audit trail of every recovery the watchdog attempted.
  • watchdog.js Node controller, called every 5 min by OS cron and/or a row in ALERTSCHEDULE.
  • OS cron is the disaster-recovery layer: if the Node app is unreachable, the cron entry pages the admin so the watchdog itself can never silently disappear.
